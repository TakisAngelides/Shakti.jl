1. Preferences

Set once, before using Shakti, then restart Julia (set_preferences! writes LocalPreferences.toml).

backend:

  • "Threads" (default) CPU kernels; the only backend the sparse direct solvers (and CUDSS) work with
  • "CUDA", "Metal" fields live on the GPU; the matrix-free solvers work there: BiCGStabIterativeSolver(grid) for the default sheet, CGIterativeSolver(grid, MatrixFreeLinearSystem) for the filled sheet

floattype:

  • "Float64" (default)
  • "Float32" halves memory, looser tolerances

cudss:

  • true (default) load CUDA.jl/CUDSS.jl under "Threads", so CUDSSDirectSolver works on a GPU node
  • false CPU-only work, saves minutes of load time

Threads: start Julia with -t N.

2. Grid

  • Grid(nx, ny, lx, ly) regular grid of nx x ny cells. lx and ly are the distances between the first and the last cell centre, not the extent of the cells' outer faces: dx = lx / (nx - 1), dy = ly / (ny - 1), and grid.x runs from 0 to lx, grid.y from 0 to ly. The cell centres are grid.x, grid.y
nx, ny = 80, 20
lx, ly = 20000.0, 5000.0
grid = Grid(nx, ny, lx, ly);

3. Mask

One code per cell. It sets the boundary conditions:

  • GROUNDED grounded ice where the subglacial hydrology of the hydraulic head and the gap between ice and bed are solved for
  • LAND ice-free land which is an outlet at atmospheric pressure (we use the gauge p_atm = 0)
  • OCEAN ocean or floating ice which is an outlet at the sea-water pressure of the bed
  • OTHER_BASIN ice outside the basin or no data and this cell is closed so no water crosses in
  • FROZEN_BED frozen bed cell with p_w = 0 that is closed (set by update_frozen_mask! described in step 12)

The grid edge is closed, so every grounded region needs an outlet. Water leaves through LAND/OCEAN faces and never enters so outflow_only_land and outflow_only_ocean are by default true and described in step 5.

mask = fill(GROUNDED, nx, ny)
mask[1, :] .= LAND                  # terminus at x = 0
mask[end, :] .= OTHER_BASIN
mask[:, [1, end]] .= OTHER_BASIN;

4. The state and initial conditions

This step only creates the input arrays below, all in SI units. They are put into a State by set_initial_conditions! in step 6, once the parameters (step 5) and the sliding law (step 6) exist.

  • zb, zs bed and surface elevation [m]
  • b initial gap height [m]; keep it above b_min (step 5)
  • A_visc ice rate factor in Glen's flow law [Pa^-3 s^-1]
  • G geothermal flux [W/m2]
  • ub_x, ub_y basal sliding speed on the x- and y-faces [m/s]
  • ieb water input from above such as from moulins [m/s]
  • taub_x, taub_y basal shear stress on the faces [Pa]; every sliding law (step 6) computes them from N and the sliding speed in its own analytical form, at the start and in each Picard iteration. These two arrays are only the starting values PrescribedSlidingLaw keeps fixed (e.g. from an ice-flow model); for every other law the input is overwritten, so pass zeros
zb     = zeros(nx, ny)
zs     = [6 * (sqrt(x + 5000.0) - sqrt(5000.0)) + 1 for x in grid.x, y in grid.y]   # SHMIP (de Fleurian et al. 2018), the ice-sheet margin geometry
b      = fill(0.01, nx, ny)
A_visc = fill(5e-25, nx, ny)
G      = fill(0.05, nx, ny)
ub_x   = fill(1e-6, nx + 1, ny)
ub_y   = zeros(nx, ny + 1)
ieb    = fill(1.0 / (365 * 86400.0), nx, ny)   # 1 m/a
taub_x, taub_y = zeros(nx + 1, ny), zeros(nx, ny + 1);

6. Sliding law and melt input

Sliding law

The sliding law gives the basal shear stress tau_b, which feeds the frictional melt. Each law below gives its magnitude $\tau_b$ from the effective pressure $N$ [Pa] and the sliding speed $u = \lVert \mathbf{u}_b \rVert$ [m/s], and points it along $\mathbf{u}_b$. It is recomputed in every Picard iteration. Coefficients (C, C_max, mu, ...) are uniform scalars or cell fields of size (nx, ny). Every law that depends on $N$ uses $\max(N, 0)$: a bed under water above overburden carries no shear. Some rows show one constructor for another law's form.

Law$\tau_b$Shakti.jlReference
Weertman$C u^m$WeertmanSlidingLaw(grid, C; m = 1/3)Weertman (1957)
Linear viscous$\beta u$WeertmanSlidingLaw(grid, beta; m = 1)
Linear in $N$ (ISSM's Shakti law)$C^2 N u$LinearSlidingLaw(grid, C)Sommers et al. (2023)
Budd (generalized power law)$C N^q u^m$BuddSlidingLaw(grid, C; m = 1/3, q = 1)Budd et al. (1979)
Till deformation$u = A \tau_b^a N^{-b}$BuddSlidingLaw(grid, A^(-1/a); m = 1/a, q = b/a)Boulton and Hindmarsh (1987)

Speeds (u0, u_t) are in m/s, like ub_x. FunctionSlidingLaw takes any magnitude f(N, u, C); on a GPU it must be a plain function or a closure over plain numbers.

Melt input

The melt input is the water that enters the bed from above, such as surface melt reaching the bed or moulins (ieb, step 4 [m/s]). It is a new input at the start of every step and is added to whatever a coupled model sets with set_ieb_external! (step 12).

Melt inputConstructorInputs

One moulinGaussianMoulinMeltInput(grid, x0, y0, sigma, Q_max, ramp_duration)see below

SeasonalMeltInput is the seasonal experiment of (Sommers et al., 2018) (Sect. 3.3) on the SHMIP geometry (de Fleurian et al., 2018); see the Seasonal melt page. The input is the same in every cell. With the year fraction $f$ (0 to 1, repeating every year), it is $i_\min$ outside the melt window and $i = \mathrm{offset} - \mathrm{amplitude}\,\cos\left(2\pi (f - t_\mathrm{start}) / (t_\mathrm{end} - t_\mathrm{start})\right)$ inside it, which rises from $i_\min$ to a peak and falls back.

7. The sheet

The sheet is the water layer between the ice and the bed. Four choices define it, one per keyword of Simulation. The defaults are the sheet of GlaDS-2 (Wells et al., 2026); each has an opt-out that gives Shakti's sheet (Sommers et al., 2018).

KeywordDefault (GlaDS-2)Opt-out (Shakti)What it changes
cavity_fillingUnfilledCavities()FilledCavities()UnfilledCavities lets the gap be only partly filled with water, where $p_w = 0$. FilledCavities assumes the gap is always full, so $p_w < 0$ (suction) appears where the gap cannot hold the head
upliftIceUplift()NoUplift()IceUplift caps the water pressure at the overburden: water above it lifts the ice, so $N \ge 0$. NoUplift lets $N < 0$. With both defaults $0 \le p_w \le p_o$
hydraulic_potentialSheetTopPotential()BedPotential()the potential that drives the flux $q$. SheetTopPotential: $q = -K \nabla (h + b)$ ((Wells et al., 2026) Eq. 7), BedPotential: $q = -K \nabla h$. See below
gap_couplingConsistentGapCoupling()ExplicitGapCoupling()what the head equation assumes about how far the gap moves during the step. See below

The stored head $h$ does not change between the two options, and neither does its definition: it is the bed-referenced head $z_b + p_w/(\rho_w g)$ in a cell whose gap is full (and $z_b + W - b$ in a partly empty cell, with $W$ the water depth). What changes is the potential whose gradient drives the flux, that is the level of the water:

OptionLevel that drives $q$In a full cell ($W = b$)In a partly empty cell ($W < b$)
BedPotential$h$$z_b + p_w/(\rho_w g)$$z_b + W - b$
SheetTopPotential$h + b$$z_b + p_w/(\rho_w g) + b$$z_b + W$

So the top of the water is $z_b + W$ where the gap is not full, and $+ b$ and $+ W$ are the same thing in a full cell, where $W = b$. The code adds $b$ (held at its start-of-step value) because $h$ already contains $W - b$ in the other regimes. The same level is used in the dissipation heat, which uses $q$. Without it, water and its dissipation heat would not follow differences in the gap height.

Face conductance

The flux between two cells needs the conductance $K$ on their shared face. k_face_choice picks how it is made from the two cells. Its default follows from the sheet: "implicit_upwind" with UnfilledCavities or IceUplift (so by default), "arithmetic" otherwise. In the table, $W$ is the water depth of a cell [m] (state.W), which equals the gap height $b$ where the gap is full. The head matrix is the linear system for the head, one row per cell, that the linear solver of step 8 solves in every Picard iteration.

Gap coupling and the water budget

Each step solves the head equation and then moves the gap with the gap scheme (step 9). The head equation contains the change of the gap, which has not been computed yet, so it has to assume it. The water budget is the bookkeeping of the water: in a step, the water stored in the sheet changes by the input minus what leaves through the outlets. The budget closes when this holds to solver tolerance. water_created(sim) (step 11) reports the difference.

  • ConsistentGapCoupling() (default with a Picard solver): the head equation assumes the change the gap scheme itself makes. The head equation and the gap then store the same water, and the budget closes at any time step.
  • ExplicitGapCoupling(): the head equation assumes the gap changes by $\Delta t \cdot \mathrm{rate}(N, b_\mathrm{old})$, as in Shakti (Sommers et al., 2018). When creep is fast ($\Delta t\, A N^3 > 1$) the gap scheme moves the gap by less than the head equation assumed, and the difference is created water. At $N < 0$ the gap can also run away. Use it only to reproduce Shakti or ISSM.

The Gap coupling page runs both on this tutorial's glacier and shows the created water against the time step.

Using the sheet in the code

sheet takes a Sheet, a bundle of the four choices. GlaDS2Sheet() is the default, so nothing needs to be passed for it:

sheet = GlaDS2Sheet()     # UnfilledCavities, IceUplift, SheetTopPotential, ConsistentGapCoupling
sheet = ShaktiSheet()     # FilledCavities, NoUplift, SheetTopPotential, ConsistentGapCoupling
sheet = ShaktiSheet(original = true)   # FilledCavities, NoUplift, BedPotential, ExplicitGapCoupling
sim = Simulation(grid, state, nsteps, dt, p, mi, sl; ps = ps, sheet = sheet)

ShaktiSheet(original = true) already contains BedPotential() and ExplicitGapCoupling(): nothing has to be passed on top of it. It reproduces the equations of Shakti bit for bit. A keyword passed to Simulation replaces the field of sheet it names, so one choice can be changed without building a new sheet:

sim = Simulation(grid, state, nsteps, dt, p, mi, sl; ps = ps, sheet = ShaktiSheet(), hydraulic_potential = BedPotential())
sim = Simulation(grid, state, nsteps, dt, p, mi, sl; ps = ps, cavity_filling = FilledCavities(), uplift = NoUplift())   # the GlaDS-2 sheet with two fields replaced
sim = Simulation(grid, state, nsteps, dt, p, mi, sl; ps = ps, k_face_choice = "upwind")

Which to choose:

  • default: bounded $p_w$, a closed water budget, large steps (hours to days)
  • Shakti's sheet: ShaktiSheet(), with which Cholesky and CG are allowed
  • the original equations bit for bit: ShaktiSheet(original = true)
sheet = GlaDS2Sheet();

8. Solvers

The head equation is nonlinear, and a Picard iteration solves it: each iteration freezes the coefficients, solves a linear system for the head with the linear solver and repeats until the head stops changing. Both objects are created explicitly:

ls = LUDirectSolver(grid)                       # linear solver
max_iter, tol = 200, 1e-6   # Picard iterations per step and tolerance
ps = PicardSolver(max_iter, tol, ls, grid)           # Picard solver, passed to Simulation as ps = ps

PicardSolver(iters, tol, ls, grid; alpha, atol, check_every) works for any e_v (englacial storage), zero or not:

ArgumentDefaultMeaning
iters-the largest number of Picard iterations per step. A step that does not converge within it is counted in unconverged (step 11) and warns
tol-relative tolerance: the iteration stops when the largest head change of an iteration, divided by the largest head, is below tol
ls-the linear solver of the table below
grid-the grid of step 2
alphanothingunder-relaxation in (0, 1]. The new head is alpha times the solve plus 1 - alpha times the previous iterate. Use alpha < 1 when the iteration stalls or oscillates; it needs more iterations. nothing is no relaxation
atol0absolute tolerance [m of head]. If > 0 it replaces tol: stops when the largest head change is below atol. Useful because the relative test depends on the elevation of the glacier, about 4.5 km on Drang Drung
check_every1test convergence every this many iterations. Each test needs a GPU-to-CPU transfer, so a larger value can save time on a GPU

Linear solvers

ls solves the linear system of one iteration. Which are possible depends on whether the head matrix is symmetric, which step 7 gives per k_face_choice: the default sheet's matrix is not symmetric, Shakti's sheet's is. Simulation refuses Cholesky and CG with the default sheet and names the opt-outs.

Preconditioners

An iterative solver needs a preconditioner: an approximate inverse of the matrix that makes it converge in few iterations. A direct solver has none. The choices are made when the solver is built, by keywords:

SolverKeywordDefaultPreconditioner
CGIterativeSolver(grid, SparseAssembledLinearSystem)amg = trueonalgebraic multigrid (Ruge-Stuben, AlgebraicMultigrid.jl): near-constant iteration count as the grid grows. CPU only
amg_refresh_every = 11rebuild the multigrid hierarchy every this many solves; a larger value saves time when the matrix changes slowly
chebyshev_degree = knothingChebyshev polynomial of degree k instead of amg (set amg = false); it needs no dot products. Its optional keywords are chebyshev_nsteps_estimate = 15 (Lanczos steps), chebyshev_bounds = :gershgorin (or :lanczos) for the eigenvalue bounds and chebyshev_eig_ratio = 30

CGIterativeSolver(grid, MatrixFreeLinearSystem) and BiCGStabIterativeSolver(grid)multigrid = trueonaggregation multigrid, run on the GPU: 2 x 2 cells are merged per level. It holds the iteration count at 5 to 12 from 80 x 20 to 1600 x 400 cells
nsmooth = 22Gauss-Seidel smoothing sweeps before and after each coarse correction
coarse_scale = 2.02.0scale of the coarse correction; above 1 it compensates for the coarse grid undershooting smooth errors. The defaults gave the fewest iterations

BiCGStabIterativeSolver also takes rtol and atol (the tolerances of its own residual, default sqrt(eps)) and itmax (the iteration cap, 0 is Krylov.jl's default of twice the number of cells). A solve that stops before its tolerance warns.

Other solver keywords of Simulation:

  • head_extrapolation_order = 1 (default) the first guess of each head solve is the head extrapolated in time from the last converged steps (1 linear, 2 quadratic): fewer Picard iterations, the same answer. 0 starts from the previous head
  • cell_N_clamping = NoCellNClamping() (default) CellNClamping(Dict((i, j) => (nmin, nmax))) clamps N in the named cells only, on top of the global N_min/N_max of step 5: a patch for a few cells that misbehave, leaving the rest of the domain free to reach low or negative N
  • diffusion_scheme = NoDiffusion() (default) WithDiffusion(ls2) adds Suhmo's channel-wall diffusion of the gap (Felden et al., 2023). It solves a second linear system, for the gap, so ls2 is a second solver instance next to the head solver's ls; see the Suhmo page
ls = LUDirectSolver(grid)
max_iter, tol = 200, 1e-6   # Picard iterations per step and tolerance
ps = PicardSolver(max_iter, tol, ls, grid);

9. Gap scheme and time step

gap_scheme (keyword) sets how the gap height $b$ is advanced in time:

  • FullyImplicitGapScheme() (default) the creep closure and the opening by sliding are both evaluated at the new value of $b$. It is unconditionally stable: it holds for any time step dt, for any bump height br and any sliding speed. It needs no iteration, because the sliding opening is piecewise linear in $b$ and is solved in closed form
  • ExplicitGapScheme() forward Euler, with the opening taken at the old $b$. It overshoots the bump height br once $dt\, u_b / l_r > 1$, so it is stable for small steps only

Under WithDiffusion this choice is ignored, because the diffusion term involves the spatial derivative of $b$. The gap equation is then non-local in space: each cell depends on its neighbours, so it must be solved as a linear system $Ax = b$ for all cells at once, as the head equation is (this is the second solver ls2 of step 8), and it has its own scheme.

Time step (timestep_scheme keyword):

  • FixedTimeStep() (default) dt every step; with the default sheet hours to days work
  • AdaptiveTimeStep(grid, state; dt_min, dt_max, target_time, safety_factor = nothing) dt is halved when the head solve does not converge (the step is retried) and grown after a few fast steps, always between dt_min and dt_max
ArgumentMeaning
dt_min, dt_maxsmallest and largest step allowed, in seconds
target_timethe total simulated time (seconds, counted from the start of this run) that the run should cover. run! stops once the simulated time reaches it, and the last step is shortened to land exactly on it. The number of steps is not known in advance, so nsteps of the Simulation is only an upper bound, e.g. ceil(target_time / dt_min)
safety_factornothing (default): no extra cap, dt is set by the head solve alone. A number, e.g. 0.3: also require $dt \le \text{safety\_factor}/r$, where ``r = A
use_percentile, percentiletake the percentile-th quantile of $r$ instead of its maximum, so that a single stiff cell does not shrink the step for the whole domain (needs a sort each step, so it is slower)

For example, one year with a step that adapts between 10 minutes and 2 days and is also capped by the gap rate:

ts = AdaptiveTimeStep(grid, state; dt_min = 600.0, dt_max = 2 * 86400.0, target_time = 365 * 86400.0, safety_factor = 0.3)

The tutorial uses FixedTimeStep().

gs = FullyImplicitGapScheme()
ts = FixedTimeStep()
dt, nsteps = 86400.0, 365;

observer (keyword), given the State field names to record (obs, e.g. "N", "b", "h", "Re", "q_x", "W") and the step indices to record them at (times, 0 = initial state):

11. Run and check

After each gap update check_gap_height looks for a gap runaway: it errors if b is not finite in a grounded cell or exceeds the ice thickness there by more than 1 km (every later step would carry it), and warns once if it exceeds the thickness by less. Under FilledCavities, check_filled_sheet also warns once when cells reach $p_w < 0$ or a step creates water. A gap that is always full must hold a fixed volume of water. Where the inflow is too small to keep it full against the creep closure, it can only create water, drop to a negative water pressure (suction, $p_w < 0$), or let the gap partly empty. UnfilledCavities takes the last option, so it creates no water and has no suction.

Water budget

Every simulation keeps a record of the water it creates or loses by mistake, sim.wb, which is read with water_created(sim). The model is correct if the water stored in the gaps changes only by the melt input minus what leaves through the outlets, and the budget measures how far it is from that. It reports:

  • per step: created, the water created beyond the sources and fluxes, and input, the water that enters the grounded region (both in m³)
  • over all steps: total_input, and total_created, the net created water (created minus lost)
  • gross_created and gross_lost: created and lost water added up separately, cell by cell and step by step. Water created in one place and lost in another cancels in total_created but not here
  • unconverged: the number of steps whose head solve did not converge (each such step also warns once)

verbose = true in Simulation prints, at each step, the Picard iterations, the dt under AdaptiveTimeStep, the water created and its fraction of the input, the count of unconverged steps once there is one, and under FilledCavities the number of cells with $p_w < 0$.

run!(sim)

gr = Array(state.mask) .== GROUNDED
(converged = sim.hs.ps.converged,
 N_over_po = extrema(Array(state.N)[gr] ./ Array(state.po)[gr]),
 b = extrema(Array(state.b)[gr]))
(converged = true, N_over_po = (0.7718059859638939, 1.0), b = (0.002153544438888274, 0.10443822242589029))

Checkpoints and restarts

run! can save a checkpoint every few steps, so that a run killed by a job time limit or a crash does not start again from day 0. The checkpoint file holds the latest state only: each save overwrites the previous one, and the last step is always saved. These code blocks are not run here, because the tutorial run is short:

run!(sim; checkpoint_every = 50, checkpoint_path = "checkpoint.nc")   # save every 50 steps

There are two ways to continue from a checkpoint. In both you first build the Simulation again exactly as before (same grid, parameters, options and output path) and then call run! with one of these keywords (never both):

KeywordUse it whennsteps of the new SimulationOutput file
restart_paththe run was killed before reaching its targetthe original total, as the run continues from the saved step up to itthe same file, reopened and appended to
extend_paththe run finished and you want to go furtherthe number of additional stepsa new file (give the new Simulation a new path), whose first frame has the saved time, so day 365 is day 365 and not day 0
## the run was killed: rebuild `sim` as above, then finish the same 365 steps
run!(sim; restart_path = "checkpoint.nc", checkpoint_every = 50, checkpoint_path = "checkpoint.nc")

## the run finished: build a new `sim` with nsteps = 365 (one more year) and a new output path, then
run!(sim; extend_path = "checkpoint.nc")

What a checkpoint stores:

  • the State, the time, and the current dt
  • the recent heads that head_extrapolation_order uses for the first guess of each head solve
  • for AdaptiveTimeStep, its controller: the step it asks for next, how many fast steps in a row it has seen, and how many steps it has rejected
  • the water budget totals of sim.wb

A resumed run therefore gives the same results and the same counts as one that was never interrupted. A checkpoint written by an older version that did not store one of these starts that part again from zero.

12. Coupling to an ice-flow model

Between steps (step!(sim) advances one) a host model can:

  • change the geometry or sliding speed in state (zs, zb, ub_x, ub_y), refreshed at the next step
  • set_mask!(state, p, new_mask) follow its grounding line and ice extent
  • update_frozen_mask!(state, p, T_prime_b) freeze and thaw cells from the basal temperature
  • set_ieb_external!(state, ieb_external) add its englacial or surface input [m/s]
  • freeze_on_capacity!(C, sim; dt) the water the bed can freeze on in dt, for its thermal model

state.N is the effective pressure the sliding law needs.

13. Plot

The slab is uniform in y, so only a profile along x is plotted: the effective pressure, the gap height and the Reynolds number on days 0, 1, 10, 30 and 100, from the NetCDF file.

  • N is smallest at the outlet but not zero. The ice there is thin (11.5 m at the first grounded cell, 1 m at the terminus itself), so $p_o$ is only 0.1 MPa. The water drains at atmospheric pressure, $p_w = 0$, so $N = p_o - p_w = p_o$ and N/p_o = 1 there. $N$ would reach zero only if $p_w$ rose to $p_o$.
  • N is set within a day. The gap takes about 100 days: it opens near the outlet, where the flux is largest and the thin ice closes it slowly (closure goes as A N^3 b), and closes inland.
  • N and Re start on day 1: on day 0 they come from the starting head, not from a solve.
N, bb, Re = (ncread(path, v) for v in ("N", "b", "Re"))
days = round.(Int, ncread(path, "time") ./ 86400)
frames = [1, 2, 11, 31, 101]                         # days 0, 1, 10, 30, 100
jm = ny ÷ 2                                          # one row along x
ix = findall(gr[:, jm])                              # grounded cells only
xkm = grid.x[ix] ./ 1e3

# tick labels, and log ticks at integer powers of ten
lin(vs) = [L"%$(round(v, digits = 1))" for v in vs]
pow10(vs) = [L"10^{%$(round(Int, log10(v)))}" for v in vs]
decades(v) = 10.0 .^ (floor(Int, log10(minimum(v))):ceil(Int, log10(maximum(v))))

# black lines whose opacity grows with time, from 0.2 on day 0 to 1 on day 100 (a square root of time, so that the
# early days stay distinguishable: linear in time would make days 1, 10 and 30 almost the same shade)
opacity(k) = 0.2 + 0.8 * sqrt(days[k] / days[frames[end]])

# one panel per quantity: label, profile along x at frame k, y scale, tick format, frames drawn
panels = [(L"N\ [\mathrm{MPa}]", k -> N[ix, jm, k] ./ 1e6,  identity, lin,   frames[2:end]),
          (L"b\ [\mathrm{mm}]",  k -> bb[ix, jm, k] .* 1e3, identity, lin,   frames),
          (L"\mathrm{Re}",        k -> Re[ix, jm, k],        log10,    pow10, frames[2:end])]

fig = Figure(size = (720, 640))
for (r, (ylabel, profile, yscale, ytickformat, ks)) in enumerate(panels)
    last_row = r == length(panels)
    yticks = yscale === log10 ? decades(reduce(vcat, profile.(ks))) : Makie.automatic
    ax = Axis(fig[r, 1]; ylabel, yscale, yticks, ytickformat,
              xlabel = last_row ? L"x\ [\mathrm{km}]" : "", xticklabelsvisible = last_row,
              xtickformat = vs -> [L"%$(round(Int, v))" for v in vs])
    for k in ks
        lines!(ax, xkm, profile(k); color = (:black, opacity(k)), linewidth = 2, label = L"\mathrm{day}\ %$(days[k])")
    end
    r == 2 && Legend(fig[1:3, 2], ax; framevisible = false)
end
