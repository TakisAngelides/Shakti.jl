Suhmo channel-wall diffusion

Suhmo (Felden et al., 2023) adds a diffusion term ∇·(D ∇b) to the gap equation: water flowing through a channel melts its walls sideways, so channels widen instead of staying one cell wide. D follows from the flux and the head gradient, so it is large in channels and close to zero in the sheet. Pass diffusion_scheme = WithDiffusion(ls) to Simulation, where ls is a second linear solver for the gap system (CholeskyDirectSolver, CUDSSDirectSolver(grid; structure = :spd) or CGIterativeSolver).

Two linear solvers

A Suhmo run solves two linear systems, so it takes two solver objects:

  • the head solve, ls inside the PicardSolver (ps): the head equation. On the default sheet its matrix is not symmetric, so it needs an LU solver (LUDirectSolver, CUDSSDirectSolver)
  • the gap solve, ls inside WithDiffusion(ls): the diffusion of b. Its matrix is symmetric positive definite, so the cheaper Cholesky (or CG) works

They are separate instances because each holds its own matrix and factorization, and each can use the method that suits its matrix. With ConsistentGapCoupling (the default) the gap system is solved at every Picard iteration, one extra solve per iteration.

The diffusion changes the result only where sqrt(D t) approaches the cell size: wide, wet channels on fine grids.

Felden et al. (2023) channelized test

Fig. 4 of (Felden et al., 2023) tests the diffusion with a moulin at (16, 8) m on a 64 m x 16 m bed sloping at 2 % under 500 m of ice, x = 0 the outlet. Without diffusion the channel below the moulin is one cell wide and 12 m deep; with it the channel is metres wide. Here Shakti runs the test with the parameters of Suhmo's shipped input (exec/0_convergence_channelized): the original SHAKTI sheet, b_min = 1 mm, Suhmo's friction heat 20² u_b² N and its tanh-ramped moulin, at the paper's Δx = 0.125 m (513 x 129 cells) in 1-hour steps for 125 days. The paper reaches steady state in about 20 days.

The run takes a few minutes on a GPU (cuDSS solvers), so the docs load its saved result instead of running it. Uncomment the block below to run it; it writes the x = 10 m transect to shakti_0125.csv.

The first step warns about suction: the gap starts at 1 cm, too small for the moulin's water, and the head drops below the bed. The gap opens within days, and no cell is in suction at the end.

Shakti, Suhmo and the paper

The transect at x = 10 m (the blue line of the paper's Fig. 4a) compared with

  • Suhmo as released (Zenodo, commit 001ef39), run with its shipped input 5lev (Δx = 0.125 m, the paper's resolution) for the same 125 days of 1-hour steps;
  • the paper's Fig. 4b ("with D"), digitized from the published figure (about ±0.025 m in b, ±0.002 m in h).

The files are in docs/src/examples/input/SUHMO.

using Shakti
using CairoMakie

function read_transect(name)
    rows = [parse.(Float64, split(l, ',')) for l in eachline(pkgdir(Shakti, "docs", "src", "examples", "input", "SUHMO", name))
            if !startswith(l, '#') && !startswith(l, 'y')]
    return (y = getindex.(rows, 1), b = getindex.(rows, 2), h = getindex.(rows, 3))
end
cases = ["Shakti" => read_transect("shakti_0125.csv"),
         "Suhmo release" => read_transect("suhmo_release_5lev.csv"),
         "Felden et al. (2023), Fig. 4b" => read_transect("felden2023_fig4b.csv")]

function half_width(y, b)                  # width where b > max/2, edges interpolated linearly
    half = maximum(b) / 2
    i1, i2 = findfirst(>(half), b), findlast(>(half), b)
    edge(i, j) = y[i] + (half - b[i]) * (y[j] - y[i]) / (b[j] - b[i])
    return edge(i2, i2 + 1) - edge(i1 - 1, i1)
end

Shakti and the released Suhmo agree on the channel: 0.83 and 0.89 m deep, 4.9 and 4.2 m wide. Their heads differ by a few centimetres: Shakti's dips by 5 cm over the channel, from 1.20 m at the edges, while Suhmo's rises by 1 cm, from 1.15 m. The published figure differs from both: its channel is 1.47 m deep and 2.2 m wide, and the head dips by 0.17 m over it, from 1.12 m at the edges. Neither code reproduces that with the released inputs.

Creep cutoff

Suhmo also limits creep closure in wide channels: ModelParameters(b_c = ...) with b_c > 0 selects CreepCutoff. On some datasets it lets a channel grow without bound, so use it with care and keep b_max = Inf: check_gap_height then stops the run when b exceeds the ice thickness by more than 1 km.
